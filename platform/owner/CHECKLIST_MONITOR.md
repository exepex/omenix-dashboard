# Scheduled database check (issue #2): owner checklist

One script does everything. You type only the admin user name and password and the #fno-desk Slack webhook URL
(made once in the steps below), all at hidden prompts; press Enter at the webhook prompt if it is already saved. The monitor's own password is generated by the script, is never shown, and goes straight into the
GitHub secret. Slack gets the details of any finding, because this repository is public and its logs and issues show
only counts.

- [ ] **Once, about 3 minutes: create the Slack webhook for #fno-desk** (in the browser, signed in to your Slack
      workspace as an admin or a member allowed to add apps):
  1. Open https://api.slack.com/apps and click **Create New App**, then **From scratch**.
  2. App Name: `Omenix DB check`; pick your workspace; click **Create App**.
  3. In the left menu click **Incoming Webhooks**; switch **Activate Incoming Webhooks** to **On**.
  4. At the bottom click **Add New Webhook to Workspace** (on newer pages: **Add New Webhook**).
  5. In "Where should Omenix DB check post?" choose **#fno-desk**, then click **Allow**.
  6. Back on the Incoming Webhooks page, under "Webhook URLs for Your Workspace", click **Copy** next to the new URL
     (it starts with `https://hooks.slack.com/services/`). Paste it straight into your password manager. It is a
     secret: never paste it into chat, a file, an issue or a commit.
  If your workspace asks an admin to approve the app, approve it (or ask the admin), then repeat step 4.
- [ ] Once, if missing: `brew install gh`, then `gh auth login` (GitHub.com, HTTPS, log in with the browser).
      `python3 --version` must work (it comes with Xcode's command-line tools).
- [ ] From your clone of `exepex/omenix-dashboard`, after `git pull`, in the terminal set up for X1:
      `platform/owner/setup_monitor.sh`
- [ ] Pass = the last line reads `RESULT: db_monitor ready; first check: OK; GitHub secret saved: yes`, and the lines
      above it say `secret OMENIX_DB_ALERT_WEBHOOK saved` (when you entered the webhook) and `variable DB_CHECK_ENABLED=true set`.
  - `first check: ALERT`: the details were printed on your screen only (not in the evidence file). Copy them to
    the orchestrator privately, not into the repository; the setup itself is done.
  - `first check: UNKNOWN`: the check could not connect as `db_monitor`. Run the script again; it sets a new
    password.
- [ ] Optional: commit `platform/evidence/<date>-monitor-setup.txt`. It holds status lines only: no password, webhook URL,
      verifier or check details.

**What happens after:**
- **Every hour** GitHub runs the check (Actions, workflow `db-check`). On a finding, or when it cannot check, the run
  fails (GitHub e-mails you), the issue "Database check: alert" is opened or commented with counts only, and the
  details go to #fno-desk.
- **Every Monday** around 03:20 UTC, #fno-desk gets a heartbeat with the last successful check. If it stops coming,
  the check has stopped.
- **Password:** to change the monitor's password later, run the same script again.
- **If the webhook leaks:** in https://api.slack.com/apps open `Omenix DB check`, **Incoming Webhooks**, remove the
  URL, add a new one for #fno-desk, and run `platform/owner/setup_monitor.sh` again with the new URL.
- **After the switch:** the old repository secret `FNO_SLACK_BOT_TOKEN` is no longer used here; if it is listed, delete it in GitHub
  (Settings, Secrets and variables, Actions) so the bot token lives only in `exepex/trading`.
