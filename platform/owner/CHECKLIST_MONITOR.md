# Scheduled database check (issue #2): owner checklist

One script does everything. You type only the admin user name and password, at a hidden prompt. The monitor's own
password is generated by the script, is never shown, and goes straight into the GitHub secret.

- [ ] Once, if missing: `brew install gh`, then `gh auth login` (GitHub.com, HTTPS, log in with the browser).
      `python3 --version` must work (it comes with Xcode's command-line tools).
- [ ] From your clone of `exepex/omenix-dashboard`, after `git pull`, in the terminal set up for X1:
      `platform/owner/setup_monitor.sh`
- [ ] Pass = the last line reads `RESULT: db_monitor ready; first check: OK; GitHub secret saved: yes`.
  - `first check: ALERT`: the report above it names what was found (large objects or drift). Keep it and send it
    on; the setup itself is done.
  - `first check: UNKNOWN`: the check could not connect as `db_monitor`. Run the script again; it sets a new
    password.
- [ ] Optional: commit `platform/evidence/<date>-monitor-setup.txt`. It holds no password or verifier.

**What happens after:** every hour GitHub runs the check (Actions, workflow `db-check`). On a finding, or when it
cannot check, the run fails (GitHub e-mails you) and the issue "Database check: alert" is opened or commented. To
change the monitor's password later, run the same script again.
